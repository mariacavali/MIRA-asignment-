## Local authoring/import format

`shared/miraKnowledge.ts` defines the exact format. A JSON bundle has `formatVersion: 1`, `sources` and `items`. Items are concise original principles, source-linked summaries, or synthetic editorial judgement examples. A book/PDF source keeps title, author, edition, intended use and permission information. Every summary cites exact source ID/version plus a locator such as page/chapter. `assetReference` reserves a document reference; it neither uploads nor fetches files.

CSV uses two columns: `record_type,payload`. The first value is `source`, `card` or `judgement`; the second is a quoted JSON object matching that schema. Embedded commas, quotes and newlines are supported. Nested lists and citations therefore round-trip without delimiter guesses. A complete import is a replacement corpus proposal; omissions are shown as removals before publication. The format is intentionally bounded to 2 MB and 200 sources/items. A future Sheets adapter can produce the same bundle.

`fixtures.ts` provides synthetic test examples, not Maria's approved content or question structure. Do not seed it into a real library. Real private-client learning cases require the consent/de-identification workflow planned for Slice 5; this path accepts only synthetic editorial judgement examples.

## Editing and publication

The `miraKnowledge` tRPC router requires authenticated `admin` access and `MIRA_KNOWLEDGE_ENABLED=true`; the flag defaults off. It does not grant admins access to private client conversations. `status` returns the catalogue revision; `listReleases` recovers draft/release IDs. Import returns a draft ID and hash. Exact repeat imports reuse that draft/release. Changing a registered ID/version's contents is rejected; increment its version.

1. Call `importDraft` with JSON/CSV and `expectedRevision`.
2. Call `inspect` to see content, citations, added/changed/removed items and publication problems.
3. Explicitly `review` each source permission and each knowledge item. Review stores the authenticated reviewer, decision, reason and time. Item approval requires evaluation-case IDs; at this stage these are the editor's attestation, not an automated evaluation engine or verified Slice 5 case registry.
4. Call `publish` with the reviewed release ID, exact hash and current revision. Sources with pending permission, missing rights evidence, unreviewed items or missing evaluation attestations block publication. Imported files cannot set review/publication state.
5. Published content/reviews are immutable. Corrections use new entry versions in a new release. The parent release is retained. Concurrent stale writes fail rather than overwrite another editor's review.
6. `withdraw` adds a permanent version-specific tombstone with actor/reason. Runtime excludes withdrawn entries and cards using withdrawn sources immediately; historical releases and citations remain readable. Reintroduction requires a reviewed new version.

The internal `publishedSnapshot()` is the runtime boundary for Slice 3. It returns only the active published release after permission/review/withdrawal filtering. Corpus identity is `(releaseId, hash, revision)`; cache invalidation must include the revision because withdrawals preserve historical release hashes. All retrieved text must be treated as reference data, never instructions or client facts. The coach now reads this snapshot through a bounded retrieval node when its separate retrieval flag is enabled; see the runtime section below.
